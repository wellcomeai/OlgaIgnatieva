# VisaNews2U — личная студия Telegram-воронок

> Техническое предложение и план реализации.
> Статус: черновик на согласование.

---

## 1. Как я понял задачу

Нужна **личная платформа для одной владелицы** (не SaaS для сторонних
клиентов), в которой она сама, без программиста:

1. **Подключает Telegram-ботов**: вставляет токен от @BotFather, и бот сразу
   работает. Ботов может быть несколько (под разные продукты или запуски).
2. **Создаёт продукты**: файлы (PDF, видео, аудио, архивы), доступ в
   закрытый канал или чат, «пакеты» из нескольких файлов. Каждому продукту
   задаёт цену.
3. **Принимает оплату через Робокассу**. После оплаты бот сам выдаёт
   файлы или ссылку-приглашение, без участия человека.
4. **Собирает воронку**: какие сообщения бот шлёт, с какими кнопками, через
   какие паузы, что видит человек до оплаты, после оплаты и если не оплатил
   (дожим).
5. **Видит результат**: подписчики, оплаты, конверсия по шагам воронки,
   выручка.
6. **Делает рассылки** по базе или по сегментам (купил / не купил / тег).
7. **Админка** для системных вещей: ключи Робокассы, ботов, резервные копии,
   логи, доступ для помощника.

Всё работает в Docker на **зарубежном сервере Timeweb Cloud**. Веб-интерфейс
современный и понятный: это рабочий инструмент, а не панель разработчика.

## 2. Варианты реализации

| | **A. Готовый конструктор**<br>(Salebot, BotHelp, Puzzlebot, Leadteh) | **B. Low-code**<br>(n8n / Make + Telegram) | **C. Своя платформа**<br>на текущем шаблоне ✅ |

| Старт | За день | 1–2 недели | 3–5 недель до полной версии |
| Стоимость владения | Подписка 1–5 тыс. ₽/мес на бота, растёт с базой | Сервер и время на поддержку | Только сервер, ~600–1200 ₽/мес |
| Робокасса | Не везде, часто через «костыли» | Вручную через HTTP-узлы | Нативно, модуль уже есть в репозитории |
| Удобство для владелицы | Перегруженные интерфейсы | Сложно, по сути программирование | Только нужные функции, под её сценарии |
| Данные и база | У сервиса, экспорт ограничен | Свои | Полностью свои |
| Риски | Блокировка аккаунта, рост цен | Хрупкие сценарии | Нужна разработка и поддержка |

**Рекомендация: вариант C.** В репозитории уже лежит рабочий шаблон
(FastAPI + Next.js + PostgreSQL + Docker), в котором готовы авторизация,

## 5. Конструктор воронок: как это устроено

Воронка состоит из **шагов (блоков)**. По умолчанию это вертикальный список,
похожий на переписку: понятно с первого взгляда. Для сложных сценариев есть
переключатель «Карта», где те же шаги показаны схемой со стрелками
(React Flow).

### Типы блоков

| Блок | Что делает |
|---|---|
| 💬 **Сообщение** | Текст с форматированием, фото, видео, кружок, голосовое, документ; кнопки-ссылки и кнопки-переходы |
| ⏱ **Пауза** | «Через 10 минут», «через 1 день в 19:00» |
| ❓ **Вопрос** | Собрать имя, e-mail, телефон, свободный ответ; сохраняется в карточку подписчика |
| 💳 **Оплата** | Выбор продукта: бот присылает кнопку «Оплатить» со ссылкой на Робокассу |
| 🎁 **Выдача** | Отправить файлы продукта или одноразовую ссылку в закрытый канал |
| 🔀 **Условие** | Если оплатил / есть тег / ответил «да», ветка А, иначе ветка Б |
| 🏷 **Тег** | Повесить или снять метку, чтобы потом сегментировать |
| ↪️ **Переход** | Перейти в другую воронку или к шагу |
| 🔔 **Уведомить меня** | Прислать владелице сообщение «новая оплата 2 990 ₽ от @user» |

### Запуск воронки (триггеры)

- `/start`, в том числе с меткой: `t.me/bot?start=reels`, чтобы видеть,
  откуда пришёл человек;
- ключевое слово в сообщении;
- успешная оплата продукта;
- ручной запуск по сегменту.

### Пример готового шаблона «Продажа гайда»

```
/start → Приветствие + лид-магнит (бесплатный PDF)
       → пауза 1 час → «Как вам гайд?» [Да / Хочу больше]
       → Предложение продукта + 💳 Оплата 990 ₽
           ├─ оплатил → 🎁 выдача файлов → «Спасибо» → тег «купил»
           └─ не оплатил за 24 ч → дожим со скидкой (промокод)
                                 → не оплатил за 72 ч → тег «холодный»
```

В системе будет 3–4 готовых шаблона, чтобы начинать не с нуля.

## 6. Оплата через Робокассу

### Поток оплаты

```
Подписчик жмёт «Оплатить»
   → бэкенд создаёт Order(pending) и подписанную ссылку Робокассы
     (InvId = id заказа, Shp_bot, Shp_tg — служебные параметры)
   → человек платит на странице Робокассы (карта, СБП, SberPay, ...)
   → Робокасса шлёт ResultURL → /webhooks/robokassa
   → проверка подписи (Password #2), сверка суммы, идемпотентность
   → Order = paid → событие «оплата» → воронка выдаёт продукт
   → владелица получает уведомление в Telegram
```

### Что учесть

- **Фискализация (54-ФЗ).** В ссылку передаётся параметр `Receipt`
  (номенклатура для чека). Для самозанятых и ИП Робокасса выбивает чеки
  сама («Робочеки»), своя онлайн-касса не нужна.
- **Модуль уже есть** в шаблоне. Его нужно расширить: добавить `Receipt`,
  `Shp_*`-параметры, разовые заказы вместо подписок и, во второй версии,
  рекуррентные платежи для подписки на закрытый канал.
- **Тестовый режим** (`IsTest=1`) уже поддержан. Всё проверяем без реальных
  денег.
- В кабинете Робокассы нужно будет указать:
  `Result URL = https://<домен>/webhooks/robokassa` (POST),
  `Success URL` и `Fail URL` — страницы «Спасибо, вернитесь в бот».
- **Правила Telegram.** Формально Telegram требует продавать цифровые
  товары внутри бота за Telegram Stars. Внешняя ссылка на оплату (как у
  Робокассы) широко используется в рунете (GetCourse, Salebot и др.), но
  риск не нулевой. Во второй версии можно добавить **Stars как второй
  способ оплаты**: архитектура это позволяет.

## 7. Выдача файлов

- Файлы загружаются в кабинете (drag & drop) и хранятся на сервере или в
  S3-хранилище Timeweb. При первой отправке Telegram возвращает `file_id`,
  и дальше файл отправляется мгновенно, без повторной загрузки.
- **Ограничение Bot API: файл до 50 МБ.** Для больших видео есть два
  варианта: (а) свой `telegram-bot-api` сервер в Docker (лимит до 2 ГБ) или
  (б) закрытый канал с одноразовой ссылкой-приглашением.
- **Закрытый канал или чат:** бот создаёт персональную ссылку
  (`createChatInviteLink`, `member_limit=1`), поэтому перешлённая ссылка не
  сработает у второго человека.
- Защита контента: опция `protect_content` запрещает пересылку и сохранение
  файла в Telegram.

## 8. Архитектура

```
                          ┌──────────────── Сервер Timeweb Cloud (Амстердам) ───────────────┐
 Telegram ──webhook──▶    │  Caddy (HTTPS, авто-сертификаты Let's Encrypt)                  │
 Робокасса ─ResultURL─▶   │     ├── /            → web     (Next.js 14, кабинет)           │
 Браузер Ольги ───────▶   │     ├── /api         → api     (FastAPI)                        │
                          │     ├── /tg/{bot}    → api     (приём апдейтов от всех ботов)  │
                          │     └── /webhooks/*  → api     (Робокасса)                      │
                          │                                                                 │
                          │  worker   (arq): паузы воронок, рассылки, выдача после оплаты  │
                          │  postgres 16  ·  redis 7  ·  backup (ежедневный pg_dump → S3)  │
                          └─────────────────────────────────────────────────────────────────┘
```

### Ключевые решения

| Решение | Почему |
|---|---|
| **aiogram 3** (Python) | Самая зрелая асинхронная библиотека для Telegram, ложится в текущий FastAPI-бэкенд |
| **Webhook, а не polling** | Один процесс обслуживает сколько угодно ботов: `POST /tg/{bot_id}` с секретным заголовком `X-Telegram-Bot-Api-Secret-Token` |
| **Движок воронок как конечный автомат** | Для каждого подписчика хранится «текущий шаг» в БД, паузы ставятся задачами в очередь. Перезапуск сервера ничего не теряет |
| **Redis + arq** | Отложенные шаги и рассылки с соблюдением лимитов Telegram (~25 сообщений/сек на бота) |
| **Токены ботов шифруются** | Fernet-шифрование в БД, ключ лежит только в `.env`. Токен нигде не попадает в git и логи |
| **Caddy вместо nginx + certbot** | HTTPS «из коробки», конфиг в 10 строк. Telegram требует HTTPS для webhook |
| **Один `docker-compose.yml`** | Деплой одной командой, одинаково локально и на сервере |

### Новые модули бэкенда

```
backend/modules/
├── bots/          # подключение ботов, шифрование токенов, setWebhook, приём апдейтов
├── flows/         # воронки, блоки, движок исполнения, триггеры
├── subscribers/   # подписчики, теги, переменные, история сообщений
├── products/      # продукты, файлы, промокоды, ссылки в каналы
├── orders/        # заказы и оплаты (на базе billing/robokassa.py)
├── broadcasts/    # рассылки и сегменты
├── media/         # загрузка и хранение файлов, кеш file_id
└── analytics/     # события, конверсия по шагам, выручка
```

### Основные таблицы

`bots` · `subscribers` (bot_id, tg_id, username, source, tags, vars) ·
`flows` · `flow_steps` (type, config JSON, next/branches) ·
`flow_runs` (subscriber, flow, current_step, wake_at) · `products` ·
`product_files` · `orders` · `broadcasts` · `events` (для аналитики) ·
`messages_log`.

### Роли

Платформа личная, поэтому роли простые:

- **Владелица (admin)**: доступ ко всему.
- **Помощник (editor)**: воронки, рассылки, подписчики; без ключей
  Робокассы, без удаления и без финансовых настроек.

Существующая админка шаблона (`/admin`) превращается в раздел
«Настройки → Система».

## 9. Сервер и деплой

### Почему зарубежный сервер и почему Амстердам

- Серверы Bot API Telegram физически стоят в Амстердаме, поэтому задержки
  будут минимальными, а замедления и блокировки Telegram в РФ бота не
  затронут.
- Робокасса доступна из-за рубежа: webhook на зарубежный сервер работает.
- В Timeweb Cloud есть локации **Нидерланды (Амстердам)** и **Германия
  (Франкфурт)**. Рекомендую Амстердам, Франкфурт как запасной вариант.

### Конфигурация

| Этап | Ресурсы | Ориентир |
|---|---|---|
| Старт (до ~20 тыс. подписчиков) | 2 vCPU · 4 ГБ RAM · 50 ГБ NVMe | ~800–1200 ₽/мес |
| Рост | 4 vCPU · 8 ГБ RAM | ×2 |
| Хранилище файлов | Timeweb S3 | от ~100 ₽/мес |

ОС Ubuntu 24.04 и Docker. Плюс домен (например, `app.<домен>.ru`).

### Деплой

```bash
git clone <repo> visanews2u && cd visanews2u
cp .env.example .env        # домен, ключи Робокассы, секреты
docker compose up -d --build
```

Следующий шаг: **GitHub Actions**. При пуше в `main` сервер сам подтягивает
код и перезапускает контейнеры. Плюс ежедневные бэкапы БД в S3.

### ⚠️ Персональные данные (152-ФЗ)

Закон требует, чтобы первичный сбор и хранение персональных данных
граждан РФ шёл в базах на территории России. Telegram ID, имена, e-mail и
телефоны подписчиков считаются персональными данными. Варианты:

1. **Всё за рубежом** (проще и дешевле). Минимизировать собираемые данные
   и проконсультироваться с юристом.
2. **Гибрид:** база данных на сервере Timeweb в Москве или Петербурге, а
   приём апдейтов от Telegram на зарубежном сервере. Это надёжнее
   юридически, но чуть сложнее. Архитектура позволяет переключиться
   позже без переделок.

Решение за заказчицей. По умолчанию закладываю вариант 1 с возможностью
перейти на вариант 2.
